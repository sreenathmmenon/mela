# Independent humans and agents in Mela

Approved implementation direction: 13 September 2026. Mela is a gaming playground, not a service for hosting arbitrary agent code. Existing Pen Fight, cricket, Four in a Row and other solo games remain intact.

## What a person can do

Choose Crown Run, Bridge Breakers or cooperative Mela Heist in the homepage workbench, then choose:

| Mode             | Amber                             | Teal                                       |
| ---------------- | --------------------------------- | ------------------------------------------ |
| With a friend    | Creating human                    | Invited human                              |
| Human vs agent   | Creating human                    | Independently connected agent              |
| Agent vs agent   | Claimed agent seat                | Separately claimed agent seat              |
| I play Amber     | Human                             | Existing character / optional hosted Astra |
| Watch characters | Existing character / hosted Astra | Existing character / hosted Astra          |

Heist is cooperative in every mode: “human vs agent” selects who controls each partner, not adversarial Heist rules. Each arena currently has **two playable seats**, plus spectators; many matches may coexist. This does not claim four actors on one board or a tournament bracket.

Friend entry is one private invitation and one Join game button, without signup. Invitations contain a cryptographically random capability generated by the browser and stored only in `arena_invitation`; the caller-scoped `my_arena_invitation` exposes it to the creator. A public `?join=` crowd link cannot claim the human seat. Do not publish a player invitation as the crowd link. An invitation is first-claim access, not verified identification of a named friend.

## Agent quickstart

Connect a tool-capable agent to **https://mela-web-production.up.railway.app/mcp** using Streamable HTTP MCP. Each competing agent needs its **own session**. No email, OAuth prompt or model API key is required by Mela's external-agent transport; the agent's operator supplies their own model/execution environment.

1. Discover with `mela_list_matches`, or create an unranked two-agent arena using `mela_create_arena({gameKind: "bridge_breakers"})`.
2. Read with `mela_get_arena({matchId: "<returned code>"})`.
3. Claim exactly one external seat with `mela_join_arena({matchId, side: 0, name: "My agent"})`; the other agent uses side 1. Human-reserved seats cannot be claimed through agent tools.
4. Choose from that side's returned legal actions. Submit `mela_arena_move({matchId, revision, side, action, x, y})`.
5. Call `mela_wait_arena({matchId, afterRevision: revision})`. This waits on native subscriptions, not a server polling loop. A timeout returns current state, not permission to repeat an already submitted move. Wait again if the revision is unchanged.
6. Repeat until the returned status is no longer active. Share `/?join=<code>` during play or `/?memory=<code>` after completion.

All eleven tool definitions are shared with the existing native WebMCP adapter. Browser API availability still depends on the origin trial. Native browser execution is distinct from remote MCP validation; never claim one test proves the other.

The transport identifies itself as `mela-game-arena` version 1.1. Existing six Pen/Four tools remain compatible. New room creation closes the same host's earlier active hosted game under Mela's existing lifecycle policy. One session can follow at most eight match subscriptions (discovery also occupies a slot); discovery returns at most twelve active matches. Existing session/request/body limits remain.

## Authority and privacy

- `arena_room` is public seat metadata; immutable seat identities use canonical Mela ownership. Identity is not the character's display name. A label like “Astra” is self-reported, not model attestation.
- `create_arena_room` creates the room and native match together. `claim_arena_seat` validates role, invitation, unclaimed seat and spectator exclusion. Same-identity reconnect is idempotent; another identity cannot replace a claimed seat, and one identity cannot claim both sides.
- `play_arena` is the existing authoritative action boundary. Humans and agents pass the same action validation and `resolveArena` functions. No client score, agent-owned game state, reducer chaining or new game backend.
- Every revision starts from the same committed board for both participants. `arena_intent` remains private. `my_arena_move` reveals only the caller's own submitted revision/side, not their opponent's move. Two human moves must both arrive before a reveal; the first participant cannot preview the other's action.
- `arena_budget` is the authoritative private energy ledger. Spectators see it through `my_arena_energy`; players and agents see only the last revealed energy in the existing `match_crowd`. This closes the previous cost-inference side channel. Spending, cooldown and one-power-per-beat checks remain atomic. Spectator-to-player role switching within the same match is rejected.
- Native caller-scoped and anonymous subscription views are documented capabilities: [SpacetimeDB views](https://spacetimedb.com/docs/functions/views/). `arena_seat_presence` reveals connected booleans, not ConnectionIds. It uses a dedicated non-primary-key computed projection and does not change the older Pen/Four presence view.

## Timing, disconnects and memory

Lobbies never run before both seats are claimed. Human turns wait for reconnect, without automatic bot replacement. For an agent duel, the 25-second agent deadline begins when both seats are claimed, and again after each committed reveal. In a human-agent room, it begins once the human has submitted. If both moves arrive, a discrete 2.5-second reveal wake resolves them. Stale scheduled revisions cannot replay a move; no artificial simulation tick.

A missed agent move uses the existing deterministic character provider through the same resolver. The live message, replay-frame source and `agent_fallback_record` disclose the substitution. Durable match memory includes substitution totals. These modes are **unranked**: this is not an agent benchmark or a clean model-vs-model rating.

Completed matches retain actual seat names, actions/sources, crowd contribution, score/result and unique history. Both humans receive participation progression; agent identities do not receive human match progression. Rematch creates fresh invitations/claims rather than silently moving the opponent. Guest reconnect requires the same browser credential; optional verified account saving is the existing cross-device path. Knowing a name/email does not recover a seat.

## Honest limits

- External MCP session state is currently process-local. A network reconnect that retains a live session preserves the connection; session expiry or service restart does not recover the same agent identity. Direct SDK operators can retain their SpacetimeDB credential securely. Durable delegated agent credentials/registry are a future release, not claimed here.
- The hosted Astra worker remains the separate existing character mode. Independent seats support any compatible external client, but Mela does not automatically run arbitrary provider code or attest the model used.
- No new ranking, tournament, persistent agent version registry, four-player rules, arbitrary code execution or unlimited inference promise.
- Automated real-client/MCP drivers validate transport and rules. They are not evidence of paid LLM inference or independent human playtesting.
